# DivineWar Unity project context

Last inspected: 2026-11-21, commit `465d698` with existing local changes.

- Unity 6000.6.3f1. 2D sprites and Tilemaps; quality settings reference URP assets. Input System is active.
- First-party gameplay lives in `Assets/DivineWar/Scripts`, in the default runtime assembly. Code uses Korean identifiers and four-space indentation.
- Build scenes: `Title`, `Main`, `BattleMenu`. `Main` contains authored unit slots, terrain, UI, and serialized references on `신들의전쟁`.
- `신들의전쟁` owns input, selection, presentation, and command delivery. `전장규칙` owns authoritative plain C# battle state, movement, damage, economy, and AI. `격자길찾기` handles grid navigation; `전장지형` handles terrain and visibility.
- Multiplayer uses the custom TCP connection in `참가연결`: JSON commands prefixed with `C`, host state snapshots prefixed with `S`. Host applies commands through `전장규칙.명령`; clients render received state. Installed Netcode does not establish gameplay ownership here.
- Selected unit indices travel in `전장명령.부대`. Attack commands with nonempty selections act on owned living soldiers/workers; absent or empty selections act on the king. JSON round trips can normalize null arrays to empty arrays.
- Explicit unit attacks retain their target through the host-only `전장대상.지정공격` flag. Movement resets it; target death or lost visibility releases pursuit. Clients use the existing target and position fields for presentation.
- Unity Pipeline tools connect to this project and support compilation and C# evaluation. Unity Test Framework is installed; no first-party test assembly was found. Editor evaluation against existing Main scene Tilemaps checked 13 attack-command/navigation/damage cases; actual pointer input and two-peer play were not exercised.
- Follow `AGENTS.md`: authored scene objects should be placed directly, not generated by scripts, except appropriate prefab use. Preserve existing local scene, art, and gameplay changes.
- Resident training: select residents and click/right-click an owned completed training school, or press 4 to send them to a completed school. `전장규칙` owns a host-only `Queue<훈련신청>` per team. Orders reserve training costs and army capacity; only the queue head trains, for 6 seconds after reaching the school. New orders, resident death, or school destruction cancel and refund the reservation. Snapshot fields expose resident assignment, queue count, and remaining time. Residents remain vulnerable while waiting; conversion preserves health percentage.
- Population limits are 24 residents and 48 soldiers per team. Slot layout: king 0, hall 1, lumber mills 2–3, schools 4–5, residents 6–29, soldiers 30–77 (plus the team offset). Main authors all 156 unit/building renderers; no extra runtime unit objects are needed. Network snapshot limit is 256 KiB (a filled validation snapshot measured 67,947 bytes).
- `DivineWar/Validation/Training Queue` runs nine isolated battle-state checks using the open Main scene terrain. Validated FIFO timing, travel, cancellation/refunds, destroyed schools, dead/reused resident slots, rejected/legacy orders, capacity reservation, snapshot round trip/size, and authored renderer references. Unity compilation and a Main Play Mode HUD smoke check passed; actual two-peer training has not been exercised.
- Focused inspection sources: `ProjectSettings/ProjectVersion.txt`, `ProjectSettings/QualitySettings.asset`, `ProjectSettings/EditorBuildSettings.asset`, `Packages/manifest.json`, and the scripts listed above. Systems outside this interaction have not received a full audit.
